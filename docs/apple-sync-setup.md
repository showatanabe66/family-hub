# Watanabe Family Hub：iPhone同期の設定

## できること・現在の状態

このZIPには同期受信機能と表示機能が入っています。アップロードだけでは同期は開始しません。以下のSupabase設定とiPhoneのショートカット作成を行ってください。完成済みのインストール用ショートカットではなく、手動作成用の手順です。

Apple側 → Family Hub の一方向同期です。HubからAppleへの変更・完了操作は行いません。既存の手入力データはそのまま残り、同期データには専用の表示が付きます。

画像でチェックされているカレンダーはGmail配下の3件です。Appleカレンダーに表示されているGoogleの予定も、ショートカットで選択して取得します。

| 取得対象 | Hub |
| --- | --- |
| Gmail配下の個人カレンダー（画像のメールアドレス名）・「家族」・「Itsumi」 | 予定 |
| リマインダー「買い物リスト」 | 買い物 |
| リマインダー「渡邊家」 | タスク |

同期先はキーを発行したHubアカウントです。同じHubアカウントでログインした端末から閲覧できます。別々のSupabaseログインの家族アカウントへ共有するためのグループ設定は、今回の実装には含みません。

## 1. Supabase：最初に一度だけ

1. 現在のアプリが使うSupabaseプロジェクトを開く。
2. SQL Editorで `supabase/migrations/202611110001_apple_sync.sql` を実行する。既存の予定や買い物テーブルは変更しません。このマイグレーションは一度だけ実行してください。
3. ローカルPCでSupabase CLIを使い、リポジトリのフォルダから次を実行する。

```sh
supabase login
supabase link --project-ref aaozokleopirgsuaubnz
supabase functions deploy apple-sync --no-verify-jwt
```

`--no-verify-jwt` はショートカットからの専用キー認証を使うためです。関数内でキーを検証します。認証なしで保存できる機能ではありません。Supabase提供の `SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` をサーバー内部で使います。service_roleキーをWebサイト、GitHub、ショートカットに貼らないでください。

4. GitHub Pagesへアプリのファイルを反映する（下の一覧参照）。
5. Hubにログインし「＋ 追加」→「Appleの予定・リマインダー連携」→「同期を設定する」を開く。
6. 「同期キーを発行」を押す。表示された送信先URLとキーをiPhoneのショートカットで使う。キーは画面を離れると再表示できません。再発行すると古いキーは使えなくなります。

有効期間は90日です。期限後は新しいキーを発行してショートカットのキーを書き換えます。「同期キーを無効にする」で以後の送信を止められます（受信済みデータは残ります）。

## 2. iPhone：ショートカットを作る

iOSによってアクション名の表記が多少異なります。最初は自動化せず手動で作成・実行し、カレンダーとリマインダーの読み取りを許可してください。

「ショートカット」アプリで「Family Hubへ同期」というショートカットを新規作成します。3つの取得処理を作り、予定・買い物・タスクをそれぞれ1回ずつPOSTします。JSONは文字列連結せず「辞書」と「リスト」で組み立てます。項目名に引用符や改行があっても正しく送れます。

### 予定を取得

1. 「現在の日付」を取得して「日付をフォーマット」でISO 8601形式にする（タイムゾーンを含む形式）。これを送信用の `captured_at` に使う。
2. 対象期間を決める。例：今日から7日前〜90日後。すべての日時の整形はタイムゾーンを「Asia/Tokyo」に統一する。
3. 「カレンダーの予定を検索」で、期間内の予定を検索する。カレンダー条件は実際の選択画面から、画像の個人カレンダー・「家族」・「Itsumi」を選ぶ。3つを一度にOR条件で選べない場合は、各カレンダーごとに検索して結果を同じリストへ追加する。取得件数の制限をオフにする。
4. 「各項目を繰り返す」で、予定ごとに次の「辞書」を作り、予定の送信用リストに追加する。
   - `name`：予定のタイトル
   - `date`：開始日時をカスタム `yyyy-MM-dd` に整形
   - `time`：開始日時を `HH:mm` に整形。終日予定は空文字
   - `source_name`：予定のカレンダー名
   - `memo`：任意。場所や終了日時など。不要なら空文字
5. 下記「送信方法」で、`sources` の `schedules` にこのリストを渡して送信する。

現在のHubは予定の開始日・開始時刻を表示します。複数日予定の帯表示、繰り返しルールの編集、通知の同期はしません。繰り返し予定は検索結果の各発生分を送ります。期間外の予定はHubに残らないため、必要に応じて範囲を広げてください。

### 買い物を取得

1. 「リマインダーを検索」でリストを「買い物リスト」、完了を「いいえ」に指定。件数制限をオフ。
2. 各項目について次の辞書を作り、買い物の送信用リストへ追加する。
   - `name`：タイトル
   - `memo`：メモ（なければ空文字）
   - `source_name`：「買い物リスト」
   - `done`：ブール値の偽（文字列の「false」ではない）。またはこのキー自体を省略する
3. `sources` の `shopping` にリストを渡して送信。

画像の「お肉・ハム・ベーコンなど」はリスト内のセクションです。今回の同期ではリスト全体を取り込み、セクション分けは表示しません。

### タスクを取得

1. 「リマインダーを検索」でリストを「渡邊家」、完了を「いいえ」に指定。件数制限をオフ。
2. 各項目について次の辞書を作り、タスクの送信用リストへ追加する。
   - `name`：タイトル
   - `date`：期限があれば `yyyy-MM-dd` に整形。期限がなければ空文字
   - `memo`：メモ（なければ空文字）
   - `source_name`：「渡邊家」
3. `sources` の `tasks` にリストを渡して送信。

繰り返しリマインダーのルール・サブタスク階層・担当者は同期しません。Apple側で完了し、次回分が作られたら、次の同期で取得された内容を表示します。

### 送信方法（3つの取得処理で共通）

「URLの内容を取得」アクションを使います。

- URL：Hub画面に表示された送信先URL
- メソッド：POST
- ヘッダー：`X-Sync-Key` = 発行したキー
- ヘッダー：`Content-Type` = `application/json`
- 本文：JSON。`version` は数値の1、`captured_at` は取得開始時のISO 8601日時、`sources` は辞書。
- `sources` の中で、対象のキー（`schedules`／`shopping`／`tasks`）に**実際のリスト変数**を渡す。JSONを文字列にした値や、空文字を渡さない。

予定を送る場合の構造例（日時・内容は変数に置き換えてください）：

```json
{
  "version": 1,
  "captured_at": "2026-11-11T08:00:00+09:00",
  "sources": {
    "schedules": [
      {"name":"予定名", "date":"2026-11-15", "time":"10:00", "source_name":"家族"}
    ]
  }
}
```

成功時は `{"ok":true,"counts":{"schedules":1}}` のような結果が返ります。「結果を表示」を付けて確認します。`ok` が true でなければ同期完了とは扱わないでください。

**0件でも取得に成功した場合は空のリスト `[]` を送ります。** これにより完了・削除した項目がHubから外れます。取得失敗・権限エラーの場合は、その種類の送信処理を実行しないでください。リスト名の選択ミスで0件になった場合もHubを空にするため、初回は送信前に検索結果を「クイックルック」で確認します。

1種類につき上限2,000件、1リクエスト1MBです。上限を超えると全体が拒否され、途中まで保存されません。取得件数を途中で打ち切って送信すると残りが一覧から外れるので、上限に達する場合は取得範囲を調整します。

## 3. 手動確認してから自動化

1. ショートカットを実行し、3回の送信が成功することを確認する。
2. Hubの「受信済みデータを再読み込み」を押して予定・買い物・タスクを確認。
3. テスト用のリマインダーを追加→同期→表示されることを確認。
4. そのリマインダーを完了→再同期→Hubから外れることを確認。
5. 「ショートカット」→「オートメーション」→「時刻」で毎朝などの実行を設定。「ショートカットを実行」で作成したものを指定し、利用できる場合は「すぐに実行」を選ぶ。

常時リアルタイム同期ではありません。変更のたびに自動実行することは保証せず、設定した時刻または手動実行時の内容を取り込みます。端末のロック、権限、通信などで実行に失敗する場合があるため、最終受信時刻を確認してください。Hubは表示中に約60秒ごと、画面に戻ったときにも受信済みデータを読み直します。この再読み込み自体はiPhone側の取得を起動しません。

## GitHub Pagesへアップロードするもの

既存ファイルを同じ階層に上書き：`index.html`、`styles.css`、`ui.js`、`app.js`、`family-extra.js`、`service-worker.js`、`manifest.webmanifest`。

追加：`apple-sync.js` と `docs/apple-sync-setup.md`（docsフォルダを維持）。

`supabase` フォルダはSupabase設定・関数デプロイに使います。GitHubに置くことは可能ですが、GitHubへアップロードするだけではSupabaseに反映されません。SQLファイルや関数コードには個人の予定・キーを含めないでください。
